# SC6113 B/C Integrated Handoff

This folder is Member C's completed handoff package. It keeps Member B's tested smart contracts as the on-chain source of truth and places Member C's backend, database and verification layer beside them.

```text
SC6113-C-Completed/
├─ contracts/   Solidity, Hardhat tests, deployment scripts, ABI and B's report material
├─ backend/     TypeScript REST API, SQLite schema, authentication and receipt verification
└─ 项目中文说明.md
```

No frontend code is included in this handoff. The frontend can be added later as a separate `frontend/` directory without changing the B/C boundary.

## What is integrated

The backend consumes the ABI generated by the contract project and understands the exact three deployed contracts: `RoleManager`, `ProjectEscrow`, and `DisputeManager`. In EVM mode, a REST write is stored only after the backend confirms the MetaMask transaction's sender, destination, function, arguments, value, receipt status, confirmation count and decoded events.

The contracts remain unchanged except for developer-facing npm scripts and `.gitignore`. This preserves B's implementation and test results while making the combined folder easier to run.

## Run locally

```powershell
# terminal 1: local chain
cd contracts
npm install
npm run node

# terminal 2: deployment and demo roles
cd contracts
$env:SEED_DEMO='true'
npm run deploy:localhost

# terminal 3: backend
cd backend
pnpm install
Copy-Item .env.example .env
# edit .env: CHAIN_MODE=evm
pnpm dev
```

If Hardhat is restarted, deploy again because the chain state is reset. Confirm that the three addresses in `backend/.env` match `contracts/deployments/localhost.json`.

## Test

```powershell
cd contracts
npm test

cd ..\backend
pnpm typecheck
pnpm test
```

For the optional live B/C check, leave the Hardhat node running, deploy with `SEED_DEMO=true`, run `npm run demo:localhost`, then follow the integration-test command in `backend/README.md`.
